# Imported-draft-first activation (LIN-108)

## Scope and precedence

Intentional free-tool imports from `tool_footer`, `tool_nudge` and `tool_header` open the dashboard editor first. The persistent footer retains a separate explicit planning action. Existing plan placements (`navbar`, `mobile_nav_cta`, `plan_section`, `footer`, `hero_editor`) and `planning=1` explicitly request planning.

The planning gate preserves completed users, settings/account-switch returns, saved OAuth resumes, hosted upgrade returns, saved planning progress and legacy backfill before applying the new deferral. Explicit planning overrides deferral. The controller snapshots arrival parameters before another return consumer or the import hook rewrites the URL. No onboarding completion flag is written for deferral.

The deferred choice and original entry source live in account-scoped browser storage (`lp-draft-first:<userId>`). They survive editor navigation, dashboard navigation and reload on that browser. This is a local preference, not a cross-device onboarding completion or entitlement. When browser storage is unavailable, an in-memory fallback covers SPA navigation; reload persistence cannot be guaranteed in that environment. Saved planning retains its existing resume behavior after the user chooses it.

## Draft safety

Imports create a separate draft rather than overwriting an existing one. The hook shares one import promise across overlapping loads. Invalid encoding/document shape and missing media fail before draft creation; the original free-tool draft stays available. Media travels through the existing bounded IndexedDB handoff and is included in the new draft's initial insert. Successful resolution removes only import/media parameters and retains intent/attribution/return parameters.

Nested list text is not treated as empty by cleanup. Failed loads remain protected from deletion. Mobile remounts seed from the current active draft's document, not stale initial text; switching drafts does not leak the previous draft or media.

The shared URL codec now consumes compression streams through `pipeThrough`, so malformed compressed input is caught by the decoder rather than also producing an unhandled writer rejection.

## After value and measurement

Only after the imported draft renders usable text does a nonblocking editor strip expose optional planning and the existing higher-AI-limits Pro action. Paid users do not receive that Pro action. The existing upgrade dialog is reused, with reason-specific text that does not pretend the user has exhausted their free quota. Plan hierarchy, prices and features are unchanged. Actual terms main `ecd42c84ee7a2d44c7166fed35d1f8ea749af4d8` is integrated normally into PR #104. Monthly retains its first-payment guarantee; new lifetime purchases retain their prospective non-refundable policy and earlier purchases retain their applicable terms. Monthly-first PR #96 remains separate and unmerged at this integration's verification time. Current integrated-head evidence is in `docs/evidence/lin-108/oct06/README.md`; earlier previews and LIN-119 approval are historical, not approval of this integration.

`draft_first_eligible` is emitted in the free tool before encoding, media transfer, authentication or import success. Encoding/media/auth/import failures remain in the eligible denominator. It describes an intentional handoff attempt, not verified new/unpaid eligibility. Deduplicate by identified person/first eligible exposure for the primary account-conversion cohort and report returning/paid users separately. Subsequent attempts retain the first stored dashboard exposure and entry source. Anonymous-to-known identity uses the existing AuthProvider identification.

`draft_import_result` records the import/create success capture or the import/post-create catch, not independent durable-persistence proof. Failure-only bounded stage metadata is defined in `docs/analytics/onboarding-funnel.md`; historical stages remain UNKNOWN. `draft_meaningful_use` records a confirmed saved edit or successful nonempty editor/header whole-post clipboard write, never an unsaved keystroke. Failed saves remain failure outcomes. `draft_planning_resumed` records explicit later planning. Pro-action exposure and existing offer/checkout events retain the first activation version/enrollment ID, cohort, variant, original source and eligibility clock. The handoff stores the clock before encoding/auth, then binds it to the account without resetting it on repeat imports. Blocked storage or hand-authored URLs with no recorded exposure have unknown original eligibility time, not an invented clock.

Checkout validates the bounded EXP-10 envelope and copies it into Checkout Session and subscription/payment-intent metadata while retaining server-authenticated user_id/client_reference_id. Hosted returns retain source and correlation. These fields are attribution only, never authorization. EXP-9 offer eligibility and monthly hierarchy remain separate PR #96 work.

All content persistence paths (debounce, explicit flush, draft-switch/load and unmount) share confirmed-save accounting. Each attempt captures the draft/account and meaningful-edit intent before awaiting persistence; subsequent hydration cannot change that attempt's classification. Unmount retains the direct API write to avoid updating an unmounted draft list. Failed writes do not mark use, hydration-only saves are excluded, and the account/draft-scoped used flag deduplicates later successful saves or copies. Switching drafts resets pending meaningful intent.

`purchase_completed` remains a completion diagnostic, not processor-paid classification. Added Stripe event/session/subscription IDs, livemode and payment_status support read-only processor reconciliation: join Session user_id/client_reference_id and envelope to subscription and first positive live settled invoice, reject renewals/test/zero/unpaid sessions, separate prior-recurring/reactivation/lifetime and unmatched payments, then deduplicate account/session/subscription/event retries. Sentinel must use that processor read rather than count webhook events. Entitlement/retry behavior is unchanged. Atlas records actual production release SHA/time and overlap partitions; missing release metadata must be joined from that register, not guessed from preview. Pending-auth billing status is unknown and remains a separate denominator stratum until resolved; no verified-unpaid rate is claimed by client handoff telemetry alone.

Verified Pro surface: existing higher daily AI limits, not exclusive access to the free quick actions. config/ai.ts gives quickAction 10/day free and 300/day paid, refinement 3/day free and 200/day paid. lib/rate-limit.ts reads the RLS billing plan and passes its configured limit to check_and_record_usage. No provider probe or new entitlement is used to test this action.

Baseline: inspected main's new-user gate opens planning on imported arrivals. No historical paid-conversion rate or eligible denominator was measured by this implementation run. Vera owns preregistration and production cohort selection. Revenue hypothesis: delivering the user's existing draft before planning increases meaningful editor use and relevant Pro reach, leading to new processor-confirmed recurring accounts within seven days. Clicks, client success screens, renewals and lifetime cash are not recurring-account lift.

Before launch Atlas coordinates the separate monthly-first release and Vera records the fixed observation/attribution window. Apply accepted LIN-109 / EXP-9 revision 2 / EXP-10 registration, not the superseded October 4 rules. There is no artificial seven-day launch hold; overlapping seven-day purchase windows are confounded and cohort purchases cannot be summed. After 14 days fewer than 100 eligibles or draft meaningful-use below half requires reach/activation decision. First 200 matured monthly eligibles with fewer than five new recurring starts fails the business hurdle, not a statistical test. At day 30 stop extending enrollment if sample is missing and zero mature starts fails the paid signal; day 37 is final attribution. Existing terms and independent review/production-health gates remain. No production experiment is launched by this PR. Article-entry LIN-115 and rejected formatter helper are outside this PR.

Kill line: verified regression in free-tool copying, import/content/media persistence, checkout or entitlement causes immediate reviewed rollback. No new purchase, provider call, migration or deploy-config change is required. Main risks are import/return precedence and low offer reach. Rollback before merge is close the PR; after Atlas squash merge, revert that isolated squash SHA through review and retain all drafts, billing/payment evidence and additive metadata.
